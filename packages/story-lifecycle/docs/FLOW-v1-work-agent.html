story-lifecycle v1.0.0 · 2026-09-12 · 单一事实源分层：规则住服务器/checker · 走法住 skill · 坑住知识库
▲ 走法（story-loop skill 维护） ● 规则（story-lifecycle 服务器维护） ◆ 约定（hc-all checker 维护） ○ 知识（.story/knowledge 维护） ✚ 通知（微信/桌面，outbox） 绿虚线圈 = 重复已消/缓解（2026-09-13） 红虚线圈 = 流程定义重复点（仅存档）
读图要点：实线灰箭头 = 主流程（需求从上到下走完）；虚线彩色箭头 = 归属层之间的调用/强制关系。 四个红色虚线圈是流程定义的重复点（判定标准：改一处要不要同步改另一处）——① skill 第7步调用序列 ≈ 服务器门契约（注：编排本身合法住 skill，重复的只是「当前缺什么」这类服务器已知信息的复述）；② 开发核对表 ≈ checker 规则（环境类坑除外，归坑库）；③「完成的定义」≈ 各 owner 判据；④ 踩坑速查表 ≈ 知识库（pitfall import 单写口）。 单一事实源分层（与 kimi 会话交叉验证收敛）：状态机/门/审计住 story-lifecycle 服务器（fail-closed 权威层）；工程约定住 hc-all checker（服务器经 precheck 钩子引用，skill 只引用不抄写）；编排（调用顺序/失败排查链/停点/双基线时机）住 story-loop skill——服务器是被动 API，编排天然在调用方，删不得；坑住 知识库（单写口 pitfall import，单读口 knowledge_search）。 去重落地（2026-09-13，v1.1 第一步）：409/428 错误响应已自描述化（message + missing[] + remediation[]，每缺口给出 endpoint/method/hint 及 skip 备选，前端/管家 MCP 已适配）；skill 收口改为「GET /deliverables → advance → 照 remediation 补缺口 → 全绿」，不再维护调用序列副本；核对表瘦身（规则住 checker）；「完成的定义」标注索引属性；踩坑速查表冻结（新坑只进知识库）。GET /next 端点作为增量糖仍后置。四个重复圈由红转绿（①②已消，③④已缓）。
SOP V1.7 嵌入 + grill-me + TAPD 落位（2026-09-12，经 kimi 双轮评审修补）：需求进入段「需求意图分析」（TAPD 详情+附件用例解析→意图/验收口径/疑点）；「探索轮+Grill 轮」——三方对账表（PRD×用例×代码，带 文件:行号 证据）先行，带证据一轮收齐（挂起出口回贴 TAPD 评论 / 跳过行记 ASSUMED），产出 PRD.md「用例处置」表（唯一载体，机器可校验）；覆盖检查复用处置表仅补判漏标；test-report 双落位确认门——PUT+confirm 授权合一，report_to_docx.py 生成公司模板 docx，用户点头后 agent 调 upload-attachment-web 经网页内部端点传 TAPD 附件卡（会话由 token_manager「tapd-web」服务自动续期：专用 Edge 档案收割+账密自愈登录）；收口后 TAPD 状态按 SOP 节点回写核对；冒烟门 ≥80%；发布窗口周二/周四下午。实例锚点：tapd-1069669（附件 47 条功能用例）。
