### 问题 #1 — 交互式 spawn 不挂 PtyLogger：events.jsonl 缺失 + 卡住检测全失效

**严重度**：高
**类型**：bug（设计 13/14 盲区）

**现象**：
- `/sessions/spawn`（半自动交互式路径）起的 claude PTY **从不写** `events.jsonl` / `raw.log`——skill 的主监控手段在交互式 story 上完全失效（本次 1068018 和 8/5 老 run 的 `.story/runs/` 里只有 `anchors.jsonl`，没有任何 `pty_*` 目录；全仓历史只有 7/28 的 `tapd-1144381896001066769/pty_build` 有 events，那次是 headless/自动路径）。
- 连带：`scheduler._tick_stuck_check` 读 `getattr(pty, "log_dir", None)` 判卡住——ManagedPty **没有** `log_dir` 属性，logger 没挂时读到 `""` → `read_events` 返回空 → **detect_stuck 永远不触发**。半自动 story 卡死（300s 无输出规则）只剩 45min STAGE_TIMEOUT 兜底，与设计 13「STEP 1 卡住检测」语义不符。

**根因**：
- `spawn_recipe.spawn_agent_pty`（commit `6ac4a59f` design-14 双路径合一）是整个 spawn 契约的唯一入口，但**不创建 PtyLogger**（参数只透传 `ensure_agent_pty(logger=None)`）。
- 只有 `AutomaticStageExecutor._spawn_pty_path`（`executors.py:514-524`）在调 `ensure_agent_pty` 前手工 `PtyLogger(story_key, stage, spawn_cwd)`。
- 交互式路径（`sessions.py:_spawn_story_agent_pty` → `spawn_agent_pty`）**从不传 logger**。`git show 6ac4a59f~1` 确认 api.py 在合一前也没有 PtyLogger——历史遗留 gap，不是本次回归，但 design-14 收口是补齐它的正确时机，漏了。

**代码引用**：
- `infra/terminal/spawn_recipe.py:124-134` — `ensure_agent_pty(...)` 调用无 `logger=`
- `orchestrator/executors.py:514-524` — 自动路径手工建 PtyLogger（唯一挂了 logger 的地方）
- `orchestrator/scheduler.py:385-389` — `_tick_stuck_check` 读 `pty.log_dir`，无 logger 时静默跳过
- `infra/terminal/pty.py:181` — `self._logger = logger`，无 `log_dir` 属性

**修复方向**：
- `spawn_agent_pty` 里无条件创建 PtyLogger 并传给 `ensure_agent_pty`（或 ManagedPty 在 logger=None 时自建默认），使两条 spawn 路径日志行为一致；stuck 检测即可恢复。
- 待评估：`ManagedPty` 暴露 `log_dir` 属性（logger 存在时）。

**状态**：未修
